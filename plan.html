Status (14 Oct): done. 260 pages, 1,742 elements, no errors. What the parse looks like:

  • Each Law is a title element ("Offside"), preceded by a text element with the number ("Law11"). Page footers also carry it ("Law 11 | Offside").
  • Sections are numbered section_header elements ("1. Offside position", "2. Offside offence"), so Law 11.1 keys come straight from the headers.
  • Section text continues across pages after page_footer and page_number elements, so assign text to sections by element order and drop footers, page numbers and figures.
  • The 256 figures are mostly IFAB logos and photos, with no offside diagrams in Law 11.
  • The course's _extract_chunks keeps only text elements and would lose every heading, so Stage 2 needs its own splitter.
  • The PDF already contains "Outline summary of Law changes" (p166) and "Details of all Law changes" (p169–186), plus the glossary (p194–207) and the practical guidelines (p208 onwards).

No Law filter on search_laws: many questions span several Laws (handball on the line is Law 12 for the offence and sanction, Law 14 for the penalty), so a wrong filter would hide the right section. In the retrieval experiment the filter only helped when it was given the right Law.

Orchestration (proposed, to review with Maria): a fixed workflow with one model-directed step.

  • Code-controlled: load the session's history from Lakebase, then always run search_laws on the whole question, so the model never answers a Laws question from memory (2 of 5 wrong in gateway_experiment.html). Pass the results to the model, run the tool loop (at most 6 iterations, fallback answer at the cap), save the question and the final answer, return it. Tool errors go back to the model as the tool result instead of failing the turn.
  • Model decisions: split a multi-part question (decision, sanction, restart) into one search_laws per part when the first search doesn't cover every part; fetch a full section; ask Genie a structured question; reason over all the results and answer.
  • History: only user questions and final answers are saved, not tool calls or results. It keeps history small; the model fetches tool results again when it needs them.
  • System prompt: answer only from tool results, cite Law, section and page, and say when the Laws don't cover it.
  • Measured in Stage 7: how often the model searches again on the FA questions and whether it changes accuracy, latency and tokens. If it rarely helps, drop the loop and keep a fixed RAG workflow.

Order: the Genie space and memory first, as they don't depend on the orchestration; the agent loop after review.
